Сертифицированные огибающие при известном диаметре

Модуль вычисляет J_D(g,P) и E_D(P) по доказанной теореме о диаметре.
Нужны m>0,H0>=m,H1>=0, сдвинутое RSI и оценка нормы Гессиана
H0+H1(f-f*) на выпуклой области. Сам модуль эти предположения о
неизвестной функции не проверяет. D>0 ограничивает диаметр сверху.

Пример вызова

    from certified_diameter import Model, certify_joint_diameter
    model = Model(m="1", H0="4", H1="0")
    result = certify_joint_diameter(
        g="1", P="2", D="3/5", model=model, factor="5/4")

В этом точном примере envelope_lower=envelope_upper=463/400.
Без ограничения диаметра совместная огибающая равна 23/16.
Точная пара наблюдений допустима: 1<2*(3/5).

Оценка только по норме вызывается так:

    from certified_diameter import certify_norm_diameter
    result = certify_norm_diameter(P="2", D="3/5", model=model)

При тех же параметрах её точное значение равно 543/400. В нормовом
вызове верхняя граница полного зазора P*D выводится из данных;
пользователю не нужно дополнительно измерять зазор.

Все g,P,D являются верхними границами. Вызов с g>P*D допустим:
такая граница зазора просто избыточна. Для двух точных положительных
наблюдений необходимо g<=P*D, но API не подменяет ими смысл caps.
Теорема остаётся точной и при диаметре ровно D, когда форма области
может меняться. Для произвольно фиксированной геометрии sharpness
не утверждается.

Входы и результаты

Числа задачи и factor задаются как int, Fraction или точная строка
рационального числа. Например, "0.1" означает точно 1/10. float и
bool отклоняются. D обязан быть положительным, даже если другой cap
равен нулю. При D>0 нулевой g или P даёт нулевую огибающую.
factor должен быть строго больше единицы.

Пакет экспортирует свои Model, Precision и ResourceLimits. Следует
импортировать их из certified_diameter. Они основаны на неизменной
копии проверенного ядра; передавать объект Model из другого отдельно
загруженного пакета не требуется.

DiameterCertificate имеет метку envelope="J_D" или "E_D".
При status="certified" точные рациональные L,U охватывают
МАТЕМАТИЧЕСКУЮ огибающую, причём U/L<=factor. Только U является
верхней границей ошибки наблюдаемого источника. L не ограничивает
эту наблюдаемую ошибку снизу. При L=U=0 achieved_factor равен 1.
Метод to_dict() сериализует рациональные значения точными строками.

При status="refused" итоговые границы и achieved_factor отсутствуют.
Сохраняются reason, message, refusal_details, затраченные операции и
частичный trace. Неверные значения, неразрешённый знак интервала и
превышение ресурсов не превращаются в приблизительный сертификат.
Ошибки Python-сигнатуры, например пропущенный обязательный аргумент,
остаются обычными TypeError до начала расчёта.

Ветви вычисления

Используются h=min(g,P²/m,P*D) и отрезок
[h²/P²,min(h/m,D²)]. При H1=0 максимум аффинной функции по rho
вычисляется точно. При H1>0 совпадающие концы отрезка сразу дают
один узел. Иначе проверяется внешний интервал для S(h): верхний
конец <=0 разрешает один левый узел; положительный нижний конец
ведёт к сетке на укороченном отрезке. Неясный знак даёт отказ.
Величина h есть радиальный параметр, а не утверждение G<=P²/m.

Результат с произвольным factor всегда проходит проверку точного
рационального отношения. Отдельной алгебраической оценки без
относительной гарантии этот небольшой модуль не экспортирует.

Точность, стоимость и независимость от v16

mpmath зафиксирован на версии 1.3.0. Все интервальные контексты
принадлежат одному вызову; глобальная точность mp и iv не меняется.
Точность и лимиты ресурсов задаются заранее. Автоматических повторов,
увеличения точности или лимитов нет. Часть допуска резервируется на
округление значений; подробности приведены в DERIVATION.txt.

_legacy_core.py и _v16_api.py скопированы побайтно из неизменного
source_snapshot первого проверенного запуска v16. Происхождение и
хеши записаны в DEPENDENCY_CAPTURE.json. Старые исходники и результаты
не меняются и не импортируются из живого рабочего дерева.

Счётчики work и elementary_evaluations отражают названные операции,
включая новые сравнения границ диаметра, проверку S, корни и отказы.
Это не подсчёт всей арифметики и не битовая сложность. Исходная
функция, её градиент, LMO, LP, оптимизатор и случайные данные
не вызываются.

Первый фиксированный контроль

protocol.json содержит десять случаев и был записан до реализации.
Среди них точный выигрыш диаметра, схлопнувшийся отрезок, точное S=0,
положительный режим с сеткой, неактивный большой D, нормовая формула,
нулевой cap, неверные D и отказ по ресурсу. Старый контроль J(1,2)
используется только как сохранённый эталон, без повторного вызова v16.

До независимого PASS от /root, привязанного к финальному FREEZE.json,
импорт и научное исполнение нового API не разрешены. Скрипт требует
pre_execution_review.json со status="PASS", approved_by="/root",
reviewed_freeze_sha256 и scientific_runs_performed=0. После этой
проверки он создаёт новый runs/run_001, проверяет каждый снимок
прямо по утверждённому хешу и импортирует только этот снимок.

    python run_protocol.py

Первый прогон сохраняет все результаты и отказы. Повторная запись
поверх run_001 запрещена. Если ожидание не выполнится, не следует
менять точность или параметры и повторять опыт ради PASS: ошибка
остаётся частью результата. Проверки реализации дополняют
математическое доказательство и не заменяют его.
