Что теперь можно использовать

1. certify_joint(g=..., P=..., model=..., factor=...) возвращает внешний
   интервал для точной совместной экстремальной функции J(g,P). Порядок
   g/P нельзя перепутать позиционным вызовом. При успешном результате
   верхняя граница ограничивает ошибку исходной задачи, а отношение
   верхней и нижней границ не превышает factor. Нижняя граница относится
   к J, а не к фактической ошибке наблюдаемой точки.

2. При доказанном S(h)<=0, h=min(g,P^2/m), внешний поиск по радиусу
   не нужен: J(g,P)=V(h,h^2/P^2). API использует один скалярный узел.
   Norm-active ветвь также имеет один узел независимо от знака S.

3. algebraic_joint_bound(g=..., P=..., model=...) возвращает верхнюю
   оценку h+(h^2/P^2)S(h) с наружным округлением. Это отдельный результат
   UpperBound, без параметра factor и без обещания относительной
   точности для точной J. При H1>0 положительный или неясный знак S
   даёт честный отказ.

4. Для certify_gap(g,...) отдельно проверяется S(g)<=0. В таком случае
   B(g)=g возвращается точно, без корня и сетки. Из S(h)<=0 при h<g
   равенство B(g)=g не следует.

Содержательные контроли

При m=H0=H1=1, g=1, P=2 получен интервал

    0.903006 <= J(1,2) <= 0.903798.

Здесь десятичные границы дополнительно округлены наружу до шести знаков.
Полные точные рациональные границы находятся в case_joint_regime_one_node.
Потребовались один узел и семь делений пополам; внешняя сетка отсутствует.
Запрошен factor=5/4, фактически полученное отношение около 1.000875.
Это характеристика данного фиксированного вызова, не общий расход API.

Для тех же данных дешёвая верхняя оценка не превышает 0.908684.
Она вычислена с одним квадратным корнем и без уравнения переключения.
Соответствие формуле 2-7*sqrt(14)/24 проверено точным рациональным
неравенством. Эта оценка не выдаётся за точное значение J.

В контроле g=10, P=1 при тех же m,H0,H1 модуль правильно использовал h=1,
а не g=10; дешёвая верхняя оценка не превышает 0.634734. Это проверка
ограничения рабочего разрыва нормовой границей.

Для m=23,H0=40,H1=1,g=48,P=40 подтверждены точные интервалы tau=[3/4,3/4]
и S=[0,0]. Следовательно, допускается равенство S=0, когда его действительно
установило вычисление. Этот случай использовал один узел и шесть делений.
При специально заданной низкой точности около другого порога интервал
знака остался неясным, и модуль вернул unresolved_regime_sign.

Вне режима S<=0 обычный joint прошёл отдельный фиксированный контроль
общей сеточной ветви: 14 положительных узлов и 70 делений пополам.
Отдельно успешно проверены нули, две точные H1=0 ветви, norm-active ветвь,
отказ дешёвой функции при положительном S, отказ по лимиту числа узлов
и отклонение неточного входа float. Отказы сохраняют затраченную стоимость
и не содержат итоговых границ сертификата.

Пределы вывода

Эти контроли подтверждают исполнение конкретного заранее заданного
протокола и не заменяют доказательства теорем. Теоремы сохраняют исходную
область применимости: экстремальность по классу с варьируемой выпуклой
областью. Нет нового утверждения о приоритете результата или точности
для каждой отдельно фиксированной геометрии множества.
