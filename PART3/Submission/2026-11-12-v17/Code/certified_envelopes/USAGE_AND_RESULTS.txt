Как использовать и независимо воспроизвести v16 API

Результат сохранённого первого запуска

16 заранее фиксированных случаев вызова API, 238 проверок контрольного
скрипта, общий статус PASS. Получены 12 успешных сертификатов и 4 ожидаемых
структурированных отказа. Это 16 API cases, а не 16 запусков оптимизации.
Ни исходная функция, ни её градиент, ни LMO, LP или оптимизатор не вызывались.

Основной результат находится в runs/run_001/result.json; подробности
каждого вызова находятся в runs/run_001/case_*.json. Интервальные границы
сохранены точными рациональными числами. EVIDENCE_RU.txt объясняет ветви,
конкретные результаты и стоимость. evidence.json агрегирует уже записанные
JSON; для него модуль повторно не исполнялся.

Обычный вызов из Python

Поместите родительскую папку certified_envelopes в Python import path.

    from certified_envelopes import Model, certify_joint, algebraic_joint_bound
    model = Model(m="1", H0="1", H1="1")
    result = certify_joint(g="1", P="2", model=model, factor="5/4")
    print(result.to_dict())
    upper = algebraic_joint_bound(g="1", P="2", model=model)
    print(upper.to_dict())

Joint использует только именованные g=... и P=.... В старом v15 порядок
позиционных аргументов был P,g; переносить такой вызов без изменения нельзя.
Нужны точные рациональные входы: int, Fraction или строки. Сначала
проверяйте status. При отказе результат не содержит итоговых границ.

У Certificate интервал относится к точной экстремальной функции; только
его верхняя граница ограничивает фактическую ошибку задачи. UpperBound
от дешёвой функции содержит лишь верхнюю оценку ошибки и не обещает
заданный относительный factor. Предположения модели описаны в README_RU.txt
и сохранённых proof_references; сам API не проверяет их на исходной задаче.

Новое независимое воспроизведение фиксированного протокола

В этой поставке runs/run_001 уже существует. run_protocol.py намеренно
не перезаписывает его. Не удаляйте старые records и не пытайтесь повторить
команду поверх сохранённого первого запуска.

1. Создайте новую пустую рабочую папку.
2. Скопируйте в неё содержимое сохранённого каталога
   runs/run_001/source_snapshot/certified_envelopes.
   Это полный пакет reviewed исходников: api.py, _legacy_core.py,
   protocol.json, run_protocol.py, requirements.txt, FREEZE.json,
   pre_execution_review.json, данные контроля и ссылки на доказательства.
3. Используйте Python, совместимый с сохранённой версией из
   runs/run_001/preflight.json исходной поставки, и mpmath==1.3.0.
   Зависимость указана в requirements.txt. При необходимости установите
   её в отдельное окружение командой:

       python -m pip install -r requirements.txt

4. В новой папке выполните:

       python run_protocol.py

Не меняйте математические параметры, точности, лимиты, protocol.json или
код. Скрипт проверит reviewed хеши, создаст свой новый runs/run_001,
сделает ещё один локальный source_snapshot и импортирует только его.
Ожидаемые результаты определены заранее. Неудачу нужно сохранить; она
не служит разрешением подобрать другие параметры или точность.

Эти инструкции предназначены для будущего независимого воспроизведения.
При подготовке данной поставки выполнен только один новый научный run.
Новых исполнений после первого PASS не было. Старые v15 расчёты сохранены
как история и не входят в число новых API cases.

Что должно совпасть при воспроизведении

При одинаковых Python/mpmath и неизменном коде сопоставляйте точные
рациональные границы, статусы, причины отказов, параметры ветвей,
диагностические скобки и счётчики. Время, абсолютные пути, даты запуска
и поэтому полный SHA результата зависят от нового окружения. Совпадение
полного result.json byte-for-byte не является условием этого протокола.
Проверки не заменяют математические доказательства и не устанавливают
преимущество оптимизационного метода на данных.
