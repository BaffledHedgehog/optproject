# Сертифицированные огибающие E, B и J

Этот небольшой Python API вычисляет рациональный интервал для одной из трёх математических огибающих версии v15. Он не запускает оптимизатор и не обращается к целевой функции, градиенту, LMO, LP или случайной выборке.

**`envelope_lower` и `envelope_upper` ограничивают саму огибающую. Нижняя граница не является нижней границей ошибки исходной задачи. Для оценки ошибки используется только `envelope_upper`.**

## Один воспроизводимый вызов

Нужен Python 3.10 или новее и `mpmath==1.3.0`. Из каталога `certified_envelopes`:

```python
from api import Model, certify_gap

certificate = certify_gap("1", model=Model(m="1", H0="1", H1="1"))
if certificate.status != "certified":
    raise RuntimeError((certificate.reason, certificate.refusal_details,
                        certificate.work))

error_upper = certificate.envelope_upper
print("Envelope interval:", certificate.envelope_lower,
      certificate.envelope_upper)
print("Exact achieved factor:", certificate.achieved_factor)
print("Source error is at most:", error_upper)
```

Последняя строка имеет математический смысл, только если нижеуказанные предположения действительно выполнены и полный зазор исходной точки не превышает `1`. API эти свойства неизвестной функции не проверяет.

Из родительского каталога доступен пакетный импорт:

```python
from certified_envelopes import Model, certify_norm, certify_gap, certify_joint
```

Все три функции возвращают объект `Certificate`. Метод `to_dict()` даёт JSON-совместимое представление, в котором рациональные границы и множители записаны точными строками. Округлённые `float`-середины не выдаются за сертификаты.

## Математическая область применимости

Пусть `Q` — нетривиальное компактное выпуклое множество, `f` дважды непрерывно дифференцируема в его окрестности, а `x*` — глобальный минимум на `Q`. Обозначим `delta(z)=f(z)-f(x*)`. Требуются известные константы `m>0`, `H0>=m`, `H1>=0`, для которых на `Q`

\[
\langle \nabla f(z)-\nabla f(x^*),z-x^*\rangle
\ge m\|z-x^*\|^2,
\qquad
\|\nabla^2f(z)\|_2\le H_0+H_1\delta(z).
\]

Градиент в условном минимуме может быть ненулевым. Полный зазор —

\[
G(x)=\max_{v\in Q}\langle\nabla f(x),x-v\rangle.
\]

| Вызов | Требуемое наблюдение | Как использовать результат |
|---|---|---|
| `certify_norm(P, model=...)` | `P >= ||grad f(x)||` | `delta(x) <= E(P) <= envelope_upper` |
| `certify_gap(g, model=...)` | `g >= G(x)` | `delta(x) <= B(g) <= envelope_upper` |
| `certify_joint(P, g, model=...)` | Обе предыдущие верхние границы | `delta(x) <= J(P,g) <= envelope_upper` |

Здесь используется евклидова норма. Ошибки только направленных скалярных произведений или оценок конечного набора атомов сами по себе не обеспечивают нормовую границу `P`. Стоимость получения наблюдений не входит в стоимость этих скалярных процедур. Для случайных наблюдений нужно отдельное одновременное событие, на котором оба наблюдения верны.

Огибающие точны в классе, определённом указанными предположениями. Совместная точность при обеих точных наблюдаемых величинах в общем случае допускает размерность два; не утверждается точность для любой фиксированной одномерной области или заранее заданного `Q`.

Точное неравенство `J(P,g) <= min(E(P),B(g))` не гарантирует того же порядка для независимо вычисленных неточных верхних оценок. Возвращённая совместная верхняя граница может оказаться больше более точно вычисленной отдельной границы. Пользователь может сохранять минимум всех верных верхних сертификатов; дополнительные скалярные вычисления при этом нужно отдельно оплатить. API не вычисляет остальные огибающие скрытно.

## Входы и результат

Принимаются только целые числа Python, `fractions.Fraction` и точные рациональные строки, например `"1/4"` или `"0.25"`. `float`, `bool`, `None` вместо обязательного числа и неподходящие параметры отклоняются. Для приблизительного измерения пользователь должен сначала построить математически верную верхнюю рациональную границу.

Дополнительные аргументы:

```python
from api import Precision, ResourceLimits

precision = Precision(work_dps=100, value_dps=100)
limits = ResourceLimits(max_positive_nodes=10000,
                        max_bisection_steps=200000)
```

`work_dps` используется для коэффициентов бюджета и знаков при делении отрезка; `value_dps` — для конечных значений в сохранённых концах интервала корня. По умолчанию обе точности равны 100 десятичным разрядам. Создаются отдельные интервальные контексты; глобальные `mpmath.mp` и `mpmath.iv` не перенастраиваются. Аффинное ядро привязано к проверенной версии `mpmath 1.3.0`.

При успехе:

- `status == "certified"`;
- рациональные `envelope_lower <= envelope <= envelope_upper`;
- `achieved_factor == envelope_upper/envelope_lower <= factor`;
- для точного нуля `achieved_factor == 1`;
- `plan`, `work`, `elementary_evaluations` и `trace` описывают выполненную работу.

При отказе:

- `status == "refused"`;
- обе границы и `achieved_factor` равны `None`;
- `reason`, `message` и `refusal_details` объясняют причину;
- уже понесённые затраты и незавершённые интервалы остаются в журнале.

Частичные значения в `trace` при отказе — диагностика, а не законченный сертификат огибающей. API не увеличивает точность, число узлов или лимиты автоматически и не продолжает деление по неопределённому знаку.

## Точные и аффинные ветви

Нулевые аргументы действительно проходят исполняемую нулевую ветвь. При `H1=0` используются точные рациональные формулы с

\[
\beta=\frac{H_0^2-2mH_0-m^2}{4H_0},\qquad
\kappa=1+\frac{\beta}{m}.
\]

Тогда `E(P)=kappa*P^2/m`, `B(g)=max(1,kappa)*g`. Для `J` при `g>=P^2/m` возвращается `E(P)`; иначе при `beta<0` используется `g+beta*g^2/P^2`, а при `beta>=0` — `kappa*g`. Эти ветви не требуют интервального корня или сетки.

Для `H1>0` запрашиваемый множитель `theta>1` разделён на внутренний `theta0=(1+theta)/2` и независимый запас на округление. Используется ранее проверенное интервальное ядро переключения, с рациональным параметром `alpha` на `[0,1]` и `b=alpha*min(sqrt(H1*rho),1)`.

Нормовая ветвь вычисляет один фиксированный радиус `V(P^2/m,P^2/m^2)`. Её собственный бюджет — `ceil(log2(max(1,4*K*/(m*(theta0-1)))))` делений отрезка. Это честный бюджет данной реализации, который может быть консервативнее отдельного бюджета нормовой огибающей в статье.

Для `B` используются доказанные `J,n`; узел нулевого радиуса задаётся точным предельным значением `g`. Для ограниченной совместной ветви используются усиленные `J*,n*` и все `J*+1` положительных узлов от `g^2/P^2` до `g/m`. Базовая нижняя граница огибающей равна `g` для `B` и `g/2` для нормовой и ограниченной совместной ветвей. В нормовой ветви здесь `g=P^2/m` — вспомогательный параметр, а не наблюдаемый полный зазор.

Если `U` — верхняя оценка, а `A` — доказанная сумма поправок на сетку, внутренний корень и максимальную ширину верхнего интервального вычисления, то `U-A` также является нижней границей огибающей. Реализация возвращает максимум этой границы, известной базовой границы и сохранённых нижних оценок узлов. Условие `A <= (theta-1)*baseline` даёт точное проверяемое отношение возвращаемых границ не больше `theta`.

Интервальная ширина проверяется отдельно против `(theta-theta0)*baseline`. При недостаточном запасе выдаётся `insufficient_rounding_slack`, даже если все знаки корня были разрешены.

## Лимиты и стоимость

По умолчанию ограничены: 4096 бит точного входа; 1000 десятичных разрядов запрошенной точности; `H1*g/m <= 10000` для рабочего параметра; 10000 положительных узлов; 200000 делений; 500000 начатых скалярных вычислений; 3000000 прямых вызовов элементарных функций; 20000 бит извлечённой рациональной границы интервала. Лимиты проверяются до выделения больших степеней двойки и до цикла по узлам. Проверка плана консервативна: она может отказать, даже если случайное точное попадание в корень сократило бы работу.

Это ограничения конкретного запуска, а не ограничения доказанной математической области. При несоблюдении лимита возвращается `resource_cap`. Неопределённый интервальный знак даёт `unresolved_interval_sign`. Нефинитный интервал, несовместимая версия зависимости или внутренняя ошибка также приводят к явному отказу.

Учёт различает:

- начатые вычисления коэффициентов, функции переключения и конечной потери;
- попытки определить знак и действительно разрешённые знаки; неудачная попытка тоже оплачена;
- завершённые обновления интервала корня;
- максимумы сертификата, нижних свидетелей и погрешностей округления;
- дополнительные максимумы для нижней границы, бюджета и метаданных ресурсов;
- прямые вызовы `exp`, `sin`, `cos`, `sqrt`;
- преобразования рациональных чисел в интервалы и извлечение рациональных концов.

Начатый вызов считается и в случае исключения внутри него. Эти счётчики не являются полным числом инструкций Python, всех рациональных/интервальных арифметических операций или битовой стоимостью. Инициализация библиотеки и внутренние действия её функций не выдаются за бесплатные; они просто не входят в названные высокоуровневые счётчики. Внешние научные оракулы имеют нулевой счётчик.

## Зафиксированный протокол

`protocol.json` содержит заранее выбранные входы, ожидаемые ветви и точные причины отказа. `FREEZE.json` фиксирует исходные файлы до исполнения. `reference_data.json` переносит только необходимые неизменённые данные предыдущего скалярного протокола; исходный SHA256 сохранён. Старый протокол со своими 1092 проверками не перезапускается и не переименовывается.

После проверки замороженного протокола один полный запуск выполняется так:

```bash
python run_protocol.py --output runs/run_001
```

Каталог должен быть новым. До первого вызова API сохраняются снимок исходников и preflight receipt. Каждый результат, включая ожидаемый отказ и любой неожиданный провал, записывается отдельно. При ошибке проверочного кода сначала сохраняются сертификат/отказ и затраты API. Оставшиеся заранее выбранные случаи выполняются однократно без изменения входов. Любое исправление требует нового протокола/снимка и нового каталога; прошлые результаты не перезаписываются.

Протокол реально вызывает нулевые и постоянные ветви, нормовую, зазорную и обе совместные аффинные ветви; отдельно проверяет отказ по ресурсам, неопределённому знаку и недостаточному запасу округления. Проверки некорректных типов отделены от математических вычислений. Никакого перебора новых оптимизационных задач, LP или стохастических экспериментов в этом дополнении нет.

`DELIVERY_READY.json`, когда он присутствует, указывает точные проверенные версии, каталоги запусков, итоговый статус и оставшиеся ограничения. Само наличие исходников без такого receipt не означает, что зафиксированный протокол уже исполнялся или прошёл.
