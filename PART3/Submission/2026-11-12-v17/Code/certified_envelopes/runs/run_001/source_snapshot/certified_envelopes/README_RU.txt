Сертифицированные скалярные оценки, версия 16

Назначение

Модуль вычисляет гарантированные оценки из доказанных теорем статьи. Он не
проверяет предположения модели по данным и не запускает метод оптимизации.
Нужны m>0, H0>=m, H1>=0, сдвинутое условие RSI и ограничение нормы Гессиана
H0+H1(f-f*), в точности как в сохранённых proof_references. Минимум может
находиться на границе. g обозначает верхнюю границу ПОЛНОГО разрыва
Франка–Вульфа, P обозначает верхнюю границу нормы полного градиента.

Публичные вызовы

    from certified_envelopes import Model, certify_joint, algebraic_joint_bound
    model = Model(m="1", H0="1", H1="1")
    result = certify_joint(g="1", P="2", model=model, factor="5/4")
    cheap = algebraic_joint_bound(g="1", P="2", model=model)

Также доступны certify_norm(P, ...) и certify_gap(g, ...).
Все числа задачи и factor передаются как int, Fraction или точная строка
рационального числа. Строка "0.1" означает точно 1/10. float и bool
отклоняются: уже округлённое машинное число нельзя незаметно считать
точным входом. Настройки Precision и ResourceLimits передаются отдельно.

Переход с v15

В старом модуле публичная сигнатура была certify_joint(P,g,...). В новой
версии оба аргумента joint обязаны иметь имена: g=..., P=.... Математическое
обозначение в статье: J(g,P). Старые позиционные примеры оставлены только
в неизменной истории legacy_v15_*. Новый публичный модуль не импортирует
старое рабочее дерево. _legacy_core.py является точной копией сохранённого
скалярного ядра; старый комментарий J(P,g) внутри этого частного файла
не задаёт порядок аргументов нового API. Вызов с позиционными g/P или
неизвестным именем аргумента вызывает обычный Python TypeError до расчёта.
Обещание структурированного отказа относится к обработанным входным
значениям, знакам интервалов и ограничениям ресурсов.

Два разных результата

1. Certificate: при status="certified" точные рациональные границы L,U
   охватывают математическую экстремальную функцию E(P), B(g) или J(g,P),
   причём U/L<=factor. Нулевой результат имеет L=U=0 и achieved_factor=1.
   Только U переносится в верхнюю оценку ошибки исходной задачи. Число L
   НЕ является нижней оценкой фактической ошибки наблюдаемой точки.

2. UpperBound от algebraic_joint_bound: поле source_error_upper есть
   верхняя оценка фактической ошибки. У этой функции нет параметра factor
   и нет обещания относительной точности для точной функции J.

При status="refused" итоговые границы отсутствуют. Сохраняются причина,
затраченные вычисления и, у Certificate, частичный диагностический trace.
Частичный trace нельзя выдавать за готовый сертификат.

Новые доказанные ветви

Положим h=min(g,P^2/m). Для H1>0 и h>0 вычисляются внешние рациональные
границы для tau и S(h), заданных в DERIVATION.txt. Решение S(h)<=0
принимается, только если верхняя граница интервала S не положительна.
Если нижняя граница положительна, режим не выполнен. Если знак не решён,
вызов отказывается от ответа. Автоматических повторов с другой точностью
нет. Равенство S=0 разрешено, когда оно действительно установлено.

Для gap-only вызова отдельно проверяется S(g)<=0; тогда B(g)=g.
Для joint условие S(h)<=0 даёт J(g,P)=V(h,h^2/P^2): внешняя сетка
не нужна, достаточно одного скалярного уравнения переключения. В нормовой
ветви g>=P^2/m один узел нужен и без проверки S. Вне режима обычный joint
использует сертифицированную сетку на фактическом отрезке радиусов.

Дешёвая функция возвращает внешний вариант оценки

    h + (h^2/P^2) S(h).

Здесь используется именно верхний конец интервала S. Для H1>0 эта ветвь
доступна только при подтверждённом S(h)<=0; положительный или неясный знак
даёт отказ. Для H1=0 возвращается точная постоянная по кривизне формула.
Нулевые g или P обрабатываются раньше деления на P^2.

Точность и ресурсы

Зависимость mpmath фиксирована: 1.3.0. Каждому вызову принадлежат свои
интервальные контексты, глобальные mp.dps и iv.dps не меняются. Интервальные
границы переводятся в точные Fraction с наружным округлением исходного
интервального ядра. Есть пределы входного размера, точности, масштаба,
узлов, шагов деления пополам, скалярных и элементарных вычислений, размера
концов интервала. Превышение лимита даёт отказ. Это ограничение ресурсов
одного вызова, а не обещание полиномиальной сложности по числу битов.

Для относительной оценки часть допуска отдельно резервируется на
округление финальных значений функции. На выходе проверяется точное
рациональное отношение U/L. Увеличить точность или лимит можно только
новым явно заданным вызовом; библиотека не делает этого сама.

Воспроизводимость

protocol.json заранее задаёт 16 случаев. В них есть точные нули, H1=0,
две ветви joint, один узел при S<=0, точное равенство S=0, общий сеточный
режим и явные отказы. Скрипт run_protocol.py сначала проверяет FREEZE.json
и независимый pre_execution_review.json. Затем создаёт новый run_001,
копирует исходники в source_snapshot/certified_envelopes и импортирует
исключительно этот пакет. Повторный запуск поверх run_001 запрещён.
Численные значения старых контролей повторно не вычисляются.

    python run_protocol.py

Команда разрешена только после независимого review. Первый фактический
run сохраняет каждый результат, агрегированную стоимость и проверку
неизменности исходников. Любое несоответствие остаётся в отчёте. Ни одна
проверка не меняет параметры, чтобы получить ожидаемый ответ.

Величины work и elementary_evaluations считают названные операции, а не
все арифметические действия. Новые проверки S и их квадратные корни
учтены. Время и проверки самого контрольного скрипта записаны отдельно.
Обращений к исходной функции, её градиенту, LMO, LP и случайным данным нет.

История

LEGACY_CAPTURE.json фиксирует два неизменных снимка v15: frozen source и
полное состояние на 2026-11-12 13:41:40 UTC. Полный снимок уже содержит
выполненный старый run_001. Он хранится как история и не входит в число
новых запусков v16. Более раннее сообщение о pending-состоянии было верным
на момент чтения; позднее обновление зафиксировано отдельно.

Проверки реализации дополняют доказательства, но не заменяют их. Точность
экстремальной функции означает точность в заявленном классе задач с
варьируемой выпуклой областью. Это не утверждение о наилучшем сертификате
для одной заранее фиксированной геометрии множества.
